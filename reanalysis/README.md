# Beyond WEIRD — analysis script pack

Self-contained replacement for the lost evaluation scripts. Runs off three
files: `judgments.jsonl`, `generations.jsonl`, `gold_standard.json`. Nothing
here modifies your data; all outputs go to `results/reanalysis/`.

**Requirements:** Python ≥ 3.9, `pip install pandas numpy scipy`.

## The coverage rule

Coverage is the **credit-sum rule**, implemented in `bw_common.panel_weights`.
Per judge, independently: if that judge matched *k* of a topic's generations to
the same gold, each of those *k* generations earns 1/*k* credit from that judge
toward that gold, and 0 from that judge toward every other gold. A generation's
weight toward a gold is the mean of that per-judge credit over the judges that
rated it; a gold's credit for a model is the sum of those weights across the
topic's five generations. That sum is by construction the share of judges who
found the gold expressed by *any* generation, so it cannot exceed 1 and no cap
is applied.

This reproduces the real pipeline's `results/agg/gold_credit.csv` to
floating-point epsilon on all 1,040 rows.

> **The one-to-one rule was tested and rejected.** `bw_common.one_to_one_assign`
> implements a greedy one-to-one bipartite match and is kept only so the
> comparison stays auditable. Its output has a consistent one-directional gap of
> roughly 2pp from `results/agg/ranking.csv`. Do not use it as the coverage
> mechanism; earlier drafts of this file described it as such and were wrong.
> The function's own docstring has said so since the hypothesis was tested.

## Run order

`make reanalysis` from the repository root runs steps 2–6 and 8 in order. Run
individually — also from the repository root — as:

| # | Command | What it does | Writes |
|---|---|---|---|
| 1 | `python reanalysis/bw_common.py --inspect` | schema detection, role/family-contamination diagnostics, topic→pair/arm mapping | — |
| 2 | `python reanalysis/audit_counts.py` | verdict accounting: raw / errors / duplicates / final N | — |
| 3 | `python reanalysis/eval_coverage.py` | coverage/precision/F1 with 10k-bootstrap CIs, plus a deviation check against `ranking.csv` | `results/reanalysis/table1_model_summary.csv`, `coverage_model_topic.csv`, `per_gold_credit.csv` |
| 4 | `python reanalysis/topic_difficulty.py` | 16-topic difficulty ranking + per-pair Table 5 with deltas | `results/reanalysis/per_topic_coverage.csv`, `table5_matched_pairs.csv` |
| 5 | `python reanalysis/weird_gap.py` | pooled exact Wilcoxon, per-model gaps with BH, precision-side check | `results/reanalysis/pair_deltas_model.csv`, `pair_deltas_pooled.csv`, `per_model_gap.csv` |
| 6 | `python reanalysis/lojo_audit.py` | leave-one-judge-out: ranking, top-model and null stability | `results/reanalysis/lojo_audit.csv` |
| 7 | `python reanalysis/build_human_assignment_input.py` | build the audit's input from the adjudicated annotation sheet | `results/annotation/human_annotations.csv` |
| 8 | `python reanalysis/human_assignment_audit.py` | 5-way gold-assignment agreement, split by arm | `results/reanalysis/human_assignment_audit.csv` |

Steps 3 and 5 are self-verifying against the real pipeline's own output — if
their reported deviation is near zero, the join, schema mapping, and
family-disjointness filter are all confirmed correct on your real data.

## Relationship to the main pipeline

This pack duplicates the main pipeline's analysis from a different angle, as an
independent check; it is not part of the pipeline. Where both produce the same
quantity, `results/agg/` is authoritative and `results/reanalysis/` is the corroboration —
they agree to <1e-9 where they overlap. Two tables in the manuscript come only
from here: Table 5 (`results/reanalysis/table5_matched_pairs.csv`) and the leave-one-judge-out
analysis (`results/reanalysis/lojo_audit.csv`).

`human_assignment_audit.py` reads `results/annotation/human_annotations.csv`,
which is generated by `build_human_assignment_input.py` (step 7 above) from the
`adjudicated` column of `results/annotation/annotations_adjudicated.csv`, i.e.
the 161 of 200 items where both annotators agreed. Restricting to agreed items
is a methodological choice, not a neutral format conversion: the protocol did
not say how to resolve annotator disagreement, so the resulting figure is
conditional on inter-annotator consensus and must be reported that way. The 39
discordant rows are excluded rather than adjudicated.

## Failure modes to know

- **Nothing reproduces Table 1** in step 3 → most likely the `match` values are
  positions in each judge's *randomised* gold ordering rather than canonical
  slots. Look for an order key per verdict (e.g. `gold_order`) and tell me its
  name — de-randomisation is a three-line fix in `load_judgments`.
- **Match values are perspective_ids** (strings) → handled automatically via
  `data/gold_standard.json`'s per-topic `perspective_id` ordering; if
  `--inspect` shows unresolved values, the gold parsing needs the right key
  names.
- **`pair_deltas` exits** → gold file lacks pair/arm; fill
  `CONFIG["manual_topic_map"]` from the stub `--inspect` prints.
- **Model naming drift**: if a slug in your files disagrees with the display
  name the paper uses, add the mapping to `CONFIG["published_aliases"]` so the
  comparison against `ranking.csv` lines up.

`CONFIG` in `bw_common.py` resolves every path from the repository root, so the
pack runs unmodified from any working directory on any machine.
